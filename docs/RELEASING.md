# Выпуск версии и откат

Что выпускается ([ADR-0005](adr/0005-distribution-bundled-plugin-and-npm.md)):

- **плагин** — ветка `release` с собранным `server/index.mjs`, откуда его ставит маркетплейс;
- **npm-пакет** `@lawyer-152fz/mcp-server` — тот же бандл, для Claude Desktop, Cursor и других клиентов;
- **GitHub Release** с бандлом во вложении.

Версия у всех одна: поле `version` в трёх манифестах (`plugins/lawyer-152fz/.claude-plugin/plugin.json`,
`.claude-plugin/marketplace.json`, `packages/mcp-server/package.json`). Версия базы норм (`kb-ГГГГ.ММ.ДД`) печатается отдельно.

## Как выпустить

1. Ветка от `main`, версия во всех трёх манифестах, `pnpm check` зелёный, PR, мерж.
2. Тег на `main`: `git tag vX.Y.Z && git push origin vX.Y.Z`. Дальше работает `release.yml`:
   1. версия тега совпадает с манифестами;
   2. `pnpm check` — формат, линтер, типы, тесты, бандл, дымовой запуск, сборка npm-пакета и пробная установка из tarball;
   3. пробная публикация в npm без отправки (`npm publish --dry-run`);
   4. бандл коммитится в ветку `release`, на этом коммите ставится метка `plugin-vX.Y.Z`;
   5. постановка версии в очередь публикации в npm (`npm stage publish`, без токена); версию подтверждает владелец на npmjs.com с 2FA;
   6. GitHub Release.
3. Проверить установку: `/plugin marketplace update lawyer-152fz`, затем запрос к агенту.

Всё необратимое (npm) стоит в конце: ветку `release` можно перезаписать, версию в npm — нет.

## Один раз перед первой публикацией в npm (владелец, T8.2 и T8.4)

Пока этого нет, npm-шаги workflow пропускаются, а плагин выпускается как раньше.

1. Создать организацию `@lawyer-152fz` на npmjs.com (имя было свободно на 2026-10-24).
2. Перевести репозиторий в публичный. Подпись provenance из приватного репозитория npm не принимает.
3. Первую версию пакета опубликовать вручную с аккаунта владельца с 2FA (доверенного издателя можно настроить только для существующего пакета): `npm publish --provenance=false --access public` из `dist/npm`, собранного из тега. Сделано 08.11.2026 для 0.5.0.
4. Настроить доверенного издателя: `npm trust github @lawyer-152fz/mcp-server --file release.yml --repo nevarium-spb/lawyer-152fz --allow-stage-publish` (npm 11.15 и новее, вход с 2FA). Сделано 08.11.2026; настройка требует первой успешной публикации из CI в течение двух дней, иначе её нужно пересоздать. Токен `NPM_TOKEN` не используется и не создаётся.
5. Включить публикацию: переменная репозитория `NPM_PUBLISH` = `true`.
6. После проверки первой публикации из CI в настройках пакета выбрать «Require two-factor authentication and disallow tokens».

## Откат

### Плагин

Ветку `release` возвращают на коммит нужной версии, метка на нём ставится при выпуске:

```bash
git fetch origin --tags
git push --force origin "plugin-v0.3.0^{commit}:refs/heads/release"
```

Пользователи получают прошлую версию после `/plugin marketplace update lawyer-152fz`. Метки `plugin-v*` появились с выпуска,
в котором добавлен этот процесс; для более ранней версии нужный коммит ищется в истории ветки `release`.
Для v0.3.0 метки нет, а его коммит плагина не вошёл в историю после пересоздания репозитория 06.11.2026
(остался только в приватном архиве); бандл v0.3.0 лежит вложением в GitHub Release v0.3.0.

### npm-пакет

Версию из npm не удаляют: `npm unpublish` ограничен правилами реестра и ломает тех, кто уже на ней. Вместо этого:

```bash
# вернуть «latest» на прошлую рабочую версию: npx -y подхватит её
npm dist-tag add @lawyer-152fz/mcp-server@0.3.0 latest

# предупредить тех, кто установил плохую версию
npm deprecate @lawyer-152fz/mcp-server@0.4.0 "Не использовать: <причина>. Используйте 0.3.x."
```

Затем выпускается исправляющая версия по обычному процессу.

### GitHub Release

Плохой релиз помечают как pre-release или удаляют в интерфейсе GitHub; тег `vX.Y.Z` без необходимости не удаляют.

## Пробный выпуск без отправки

Всё, что можно проверить без реестра, проверяется локально и в каждом PR (`pnpm check`):

```bash
pnpm build:server   # бандл
pnpm build:npm      # dist/npm: пакет, как он уйдёт в npm
pnpm smoke:npm      # npm pack → установка tarball в пустой проект → запуск по stdio
```

Проверено на релизе v0.6.0 (08.11.2026): вход в npm по OIDC работает из приватного репозитория, а `npm stage publish` с provenance отклоняется (E422, только публичные репозитории). Репозиторий стал публичным 08.11.2026 (T8.4), флаг `--provenance=false` из шага `npm stage publish` убран. Проверено на релизе v0.7.0 (10.11.2026): `npm stage publish` без флага подписал provenance и поставил версию в очередь без ошибки E422; видна ли подпись после подтверждения версии, проверить на странице пакета (при E422 вернуть флаг). Тег v0.6.0 в npm не попал (ветка `release` и метка `plugin-v0.6.0` обновились), выпущена 0.6.1.
