# ADR-0006. Безопасность: недоверенный контент, SSRF, без хранения ПДн

- Статус: принято
- Дата: 2026-10-23

## Контекст

Агент читает чужие сайты и репозитории — их содержимое может содержать prompt injection.
Сервер делает HTTP-запросы по адресам от пользователя (в боте — от любого человека) — риск SSRF.
Проект про защиту ПДн и не имеет права сам их собирать без необходимости.

## Решение

1. **Недоверенный контент.** Тексты страниц и файлов возвращаются в отдельных полях с пометкой «данные цели аудита»;
   субагент и скиллы явно запрещают исполнять инструкции из них. Длина возвращаемых фрагментов ограничена.
2. **SSRF-защита в `PageLoader`.** Только `http`/`https`; проверка IP после DNS-резолва; лимиты на редиректы, размер и время.
   Политика частных адресов — параметр конфигурации: `allowPrivateNetworks: true` в плагине (аудит своего localhost),
   `false` в боте.
3. **Без хранения ПДн.** Сервер без состояния; не логирует содержимое страниц, профили операторов и тексты документов.
   Логи — только технические события и ошибки.
4. **Аудит кода — только чтение.** Сервер не пишет в проект пользователя; правки предлагает и делает Claude после подтверждения.
5. **Цепочка поставок.** Минимум зависимостей, lockfile, `pnpm audit` в CI, Dependabot, npm provenance, без postinstall-скриптов.
6. **Бот (фаза 2)** — отдельный ADR: хранение в РФ, уведомление РКН, политика, сроки хранения, удаление по запросу.

## Последствия

- \+ Аудит своего dev-сервера работает из коробки, а публичный бот защищён.
- − Часть страниц за антиботом или авторизацией не просканировать — попадает в `notChecked`.

## Отвергнутые варианты

- **Кэш отсканированных страниц на диске** — ускорил бы повторный аудит, но хранит чужие ПДн; можно добавить позже как opt-in с TTL.
