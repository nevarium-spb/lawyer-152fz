# ADR-0008. Внутренние пакеты подключаются как исходники TypeScript

- Статус: принято
- Дата: 2026-10-24
- Уточняет: [ADR-0002](0002-monorepo-hexagonal-typescript.md)

## Контекст

План предполагал сборку каждого пакета через tsup и project references TypeScript.
Но наружу публикуется только `mcp-server`, и он всё равно собирается esbuild в один файл (ADR-0005).
Остальные пакеты — внутренние: их никто не устанавливает из npm.

## Решение

- Внутренние пакеты (`core`, `knowledge`, `scanner`, `rules`, `documents`) помечены `"private": true`,
  их `exports` указывают прямо на `src/index.ts`. Отдельной сборки у них нет.
- Проверка типов — одна программа `tsc` из корневого `tsconfig.json` (`noEmit`, `moduleResolution: bundler`).
- Тесты (Vitest) и бандл (esbuild) читают TypeScript напрямую.
- Границы между пакетами по-прежнему защищает dependency-cruiser, а не сборка.

## Последствия

- \+ Меньше инструментов и конфигов: нет tsup, нет `dist/` у пакетов, нет project references.
- \+ Изменение в `core` сразу видно в остальных пакетах — без пересборки.
- − Пакеты нельзя опубликовать по отдельности как есть. Если понадобится — добавить сборку тому пакету, который публикуется.
- − Одна программа `tsc` на весь репозиторий: при росте до сотен тысяч строк можно вернуться к project references.

## Отвергнутые варианты

- **tsup + project references для каждого пакета** — оправдано для публикуемых библиотек, здесь лишняя сложность.
