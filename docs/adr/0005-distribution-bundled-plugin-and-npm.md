# ADR-0005. Поставка: бандл в плагине + npm-пакет

- Статус: принято
- Дата: 2026-10-23

## Контекст

Агент должен ставиться глобально одной командой в Claude Code и быть доступен другим MCP-клиентам.
Плагины Claude Code ставятся из git-репозитория-маркетплейса (`.claude-plugin/marketplace.json`),
MCP-серверы плагина описываются в `.mcp.json` и запускаются с `${CLAUDE_PLUGIN_ROOT}`.

## Решение

- Репозиторий одновременно является маркетплейсом: `.claude-plugin/marketplace.json` → `plugins/lawyer-152fz`.
- MCP-сервер собирается esbuild в **один файл** `plugins/lawyer-152fz/server/index.mjs` со вшитой базой норм.
  `.mcp.json` запускает его через `node ${CLAUDE_PLUGIN_ROOT}/server/index.mjs`.
- Бандл кладёт в git **только релизный CI** при выпуске версии; в обычных PR CI проверяет, что бандл не правили руками.
- **Уточнение (2026-10-26, веха M4):** бандл публикуется не в `main`, а в ветку **`release`** (workflow `release.yml`
  по тегу `vX.Y.Z`). Маркетплейс берёт плагин оттуда: `source: git-subdir`, `path: plugins/lawyer-152fz`, `ref: release` —
  этот формат подтверждён на официальном маркетплейсе Claude Code. В `main` бандла нет вовсе, в `.gitignore` он исключён.
- Параллельно `@lawyer-152fz/mcp-server` публикуется в npm (с provenance) для Claude Desktop, Cursor и других клиентов.
- Версия плагина = версия `mcp-server`; версия базы норм печатается отдельно.

## Последствия

- \+ Установка плагина не требует npm, сети при запуске и установки зависимостей; работает офлайн.
- \+ Версия сервера жёстко связана с версией плагина — нет рассинхронизации.
- − В git лежит сборочный артефакт; смягчается тем, что его меняет только CI.
- − У плагина нет `node_modules`, поэтому браузерный рендер для SPA требует отдельного решения (риск R3 в ARCHITECTURE.md, спайк).

## Отвергнутые варианты

- **`npx -y @lawyer-152fz/mcp-server` в `.mcp.json`** — зависимость от npm и сети при каждом первом запуске, медленный старт.
- **Только npm без плагина** — нет субагента, скиллов и команд; хуже опыт в Claude Code.
