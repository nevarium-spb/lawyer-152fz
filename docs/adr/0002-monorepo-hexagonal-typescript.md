# ADR-0002. Монорепозиторий pnpm, TypeScript strict, гексагональная архитектура

- Статус: принято
- Дата: 2026-10-23

## Контекст

Одно ядро — несколько оболочек (MCP-сервер, плагин, бот). Код должен быть поддерживаемым,
доступным для контрибьюторов open-source и устойчивым к смене внешних библиотек.

## Решение

- **Монорепозиторий pnpm workspaces**: `packages/*` (библиотеки), `apps/*` (приложения), `plugins/*` (плагин Claude Code).
- **TypeScript strict** (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), ESM, Node ≥ 22.12 LTS.
- **Гексагональная архитектура**: `core` содержит домен, сценарии и порты (интерфейсы) и не делает I/O.
  Адаптеры (`knowledge`, `scanner`) реализуют порты. Сборка зависимостей — только в точках сборки (`mcp-server`, `apps/*`).
- **Ошибки как значения**: сценарии возвращают `Result<T, DomainError>`; исключения — только для багов.
- **Границы проверяются машиной**: dependency-cruiser в CI запрещает, например, импорт `scanner` из `core` или `mcp-server` из `rules`.
- Инструменты: Vitest (тесты), ESLint + typescript-eslint, Prettier, Changesets (версии), tsup/esbuild (сборка).
  Точные версии фиксирует планировщик.

## Последствия

- \+ Ядро переиспользуется ботом без изменений; адаптер можно заменить (статическая загрузка ↔ браузер) без правок домена.
- \+ Контрибьютор правил трогает только `packages/rules`.
- − Больше начальной настройки, чем у одного пакета; окупается к фазе 2.

## Отвергнутые варианты

- **Один пакет** — быстрее старт, но бот и плагин перемешаются, границы размоются.
- **Nx / Turborepo сразу** — избыточно для 6 пакетов; можно добавить позже без переделки структуры.
- **Python** — у пользователей плагина потребуется Python/uv; MCP SDK на TypeScript — основной.
