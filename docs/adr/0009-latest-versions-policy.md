# ADR-0009. Политика версий: всегда последние

- Статус: принято
- Дата: 2026-10-24
- Уточняет: [ADR-0002](0002-monorepo-hexagonal-typescript.md)

## Контекст

Устаревшие зависимости — источник уязвимостей. Владелец проекта установил правило:
всегда использовать последние стабильные версии, а пользователи обновляют своё окружение сами.
Поддержка старых версий Node ради совместимости не ведётся.

## Решение

- **Node.js** — последняя версия (сейчас 26). Минимум в `engines`, `.nvmrc` и матрица CI совпадают с ней.
  При выходе новой мажорной версии Node минимум поднимается.
- **Зависимости и GitHub Actions** — последние версии, включая мажорные. Dependabot проверяет обновления
  ежедневно и группирует их в один PR; при зелёном CI обновление принимается.
- **TypeScript** — проверку типов выполняет последний компилятор **TS 7** (пакет `typescript@7`
  под алиасом `tsc7`, скрипт `pnpm typecheck`).

### Исключение: TypeScript 6 внутри линтера

TS 7 — нативный компилятор без JS-API, а typescript-eslint 8.x работает только через этот API
и поддерживает TypeScript `<6.1`. Поэтому пакет `typescript@6.0.3` остаётся **только как движок
typescript-eslint**: проверку типов он не выполняет и в сборку не попадает.

**Условие снятия:** выход версии typescript-eslint с поддержкой TypeScript 7
([typescript-eslint#10940](https://github.com/typescript-eslint/typescript-eslint/issues/10940)) — тогда `typescript`
поднимается до 7, алиас `tsc7` удаляется, скрипт `typecheck` снова вызывает `tsc`, правило `ignore` в
`.github/dependabot.yml` удаляется. Такой же подход («TS 6 рядом с TS 7») рекомендует Microsoft в анонсе TypeScript 7.0.

Подтверждено 2026-10-25: Dependabot PR #6 (`typescript` 6 → 7) упал в CI с ошибкой
«typescript-eslint does not support TS 7.0». Мажорные обновления пакета `typescript` исключены в Dependabot до снятия.

## Последствия

- \+ Исправления безопасности приходят сразу, без накопленного технического долга обновлений.
- \+ TS 7 проверяет типы примерно вдвое быстрее TS 6 на нашем проекте.
- − Пользователям нужна актуальная Node; на старых версиях агент не поддерживается.
- − Мажорные обновления могут ломать сборку — их ловит CI до слияния.

## Отвергнутые варианты

- **Поддерживать минимальную LTS-версию Node** — шире аудитория, но противоречит правилу владельца о безопасности.
- **Остаться на TS 6 целиком** — проще настройка, но компилятор не последний.
- **TS 7 без typescript-eslint** — минус строгие правила линтера, на которых держится качество кода.
