# ADR-0004. Правила аудита — реестр независимых модулей

- Статус: принято
- Дата: 2026-10-23

## Контекст

Проверок будет много, и они будут меняться вместе с законом и практикой РКН: согласие на формах,
cookie и счётчики, трансграничная передача, ссылка на политику, локализация баз и т. д.
Добавление проверки не должно требовать правки движка.

## Решение

Каждое правило — отдельный файл в `packages/rules/src/<область>/`:

```ts
export const formConsentRule: AuditRule = {
  id: 'PD-FORM-CONSENT-001',
  title: 'Форма собирает ПДн без согласия',
  appliesTo: ['site'],
  normRefs: ['152-fz/art-9/part-1'],
  check(snapshot) { /* чистая функция → Finding[] */ },
};
```

- Реестр собирает правила из явного списка (`index.ts`), без «магии» сканирования папок.
- Правило — чистая функция от снимка (`SiteSnapshot` / `CodebaseSnapshot`), без I/O.
- Обязательные тесты на каждое правило: фикстура с нарушением и фикстура без него.
- CI проверяет, что все `normRefs` существуют в базе норм.
- Эвристики помечаются `confidence: 'needs-review'`.

## Последствия

- \+ Принцип открытости/закрытости: новое правило не трогает движок.
- \+ Правила легко ревьюить и контрибьютить по одному.
- − Межправильные зависимости запрещены; сложные выводы делает модель поверх находок.

## Отвергнутые варианты

- **Правила в YAML/DSL** — проще для нетехнических авторов, но слабее типизация и выразительность; можно добавить позже как адаптер.
- **Одна большая функция аудита** — быстро вначале, быстро становится неподдерживаемой.
