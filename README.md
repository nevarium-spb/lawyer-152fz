# Lawyer 152-FZ

[![npm](https://img.shields.io/npm/v/@lawyer-152fz/mcp-server?label=npm)](https://www.npmjs.com/package/@lawyer-152fz/mcp-server)
[![CI](https://github.com/nevarium-spb/lawyer-152fz/actions/workflows/ci.yml/badge.svg)](https://github.com/nevarium-spb/lawyer-152fz/actions/workflows/ci.yml)
[![Лицензия AGPL-3.0](https://img.shields.io/github/license/nevarium-spb/lawyer-152fz)](LICENSE)

ИИ-юрист по 152-ФЗ «О персональных данных» и работе с Роскомнадзором — плагин для Claude Code и MCP-сервер для Claude Desktop, Cursor и других MCP-клиентов.

Отвечает на вопросы о персональных данных с цитатами норм и датами их редакций, проверяет сайт и код проекта на нарушения 152-ФЗ, составляет политику обработки ПДн, согласия и сведения для уведомлений Роскомнадзора.

> **Результат носит справочный характер и не заменяет консультацию юриста.** База норм и шаблоны документов ещё не прошли ревью практикующим юристом — см. [ограничения](#ограничения).

## Как это выглядит

Проверка тестовой страницы: форма «имя + телефон» без галочки согласия и без ссылки на политику, на странице подключён Google Tag Manager. Настоящий вывод `audit_html` версии 1.0.0, одна находка из четырёх, сокращено:

```json
{
  "ruleId": "PD-FORM-CONSENT",
  "kind": "violation",
  "confidence": "deterministic",
  "title": "Форма собирает имя и телефон, но не запрашивает согласие на обработку персональных данных",
  "evidence": [{ "selector": "форма №1", "untrustedExcerpt": "Ваше имя (name), Телефон (phone)" }],
  "normRefs": ["152-fz/art-9/part-1", "152-fz/art-6/part-1", "koap/art-13.11/part-1"],
  "remediation": "Добавьте рядом с кнопкой отправки отдельную галочку согласия, не отмеченную заранее, и ссылку на текст согласия…"
}
```

Остальные находки: нет ссылки на политику обработки ПДн (нарушение), Google Tag Manager передаёт данные за рубеж и счётчики работают без уведомления о cookie (риски с пометкой «требует проверки»). В конце отчёта — что проверено и что проверить не удалось. Агент пересказывает отчёт по порядку: нарушения → риски → рекомендации.

Любая норма из отчёта открывается через `get_norm` — с текстом, датой редакции и источником:

```json
{
  "id": "152-fz/art-18.1/part-2",
  "text": "2. Оператор обязан опубликовать или иным образом обеспечить неограниченный доступ к документу, определяющему его политику…",
  "editionDate": "2026-07-26",
  "sourceType": "official",
  "verifiedAt": "2026-10-29"
}
```

## Установка

Нужна последняя версия Node.js (сейчас ≥ 26): MCP-сервер запускается через `node`.

**Claude Code** — плагин с субагентом, скиллами и MCP-сервером:

```
/plugin marketplace add nevarium-spb/lawyer-152fz
/plugin install lawyer-152fz@lawyer-152fz
```

Плагин ставится из ветки `release`, где лежит уже собранный сервер (`server/index.mjs`). Отдельной установки зависимостей не нужно.

**Claude Desktop, Cursor и другие MCP-клиенты** — сервер из npm ([`@lawyer-152fz/mcp-server`](https://www.npmjs.com/package/@lawyer-152fz/mcp-server)), конфигурация клиента:

```json
{
  "mcpServers": {
    "lawyer-152fz": {
      "command": "npx",
      "args": ["-y", "@lawyer-152fz/mcp-server"]
    }
  }
}
```

База норм и шаблоны вшиты в сервер. Сеть нужна только `check_norm_freshness` и `audit_site`.

## Что умеет

- **Консультации.** Ответ опирается на текст нормы из встроенной базы и содержит цитату с идентификатором вида `152-fz/art-9/part-1` и датой редакции. Если нормы в базе нет, агент говорит об этом, а не домысливает. Пример: «Нужно ли согласие на обработку персональных данных для формы обратной связи на сайте?»
- **Аудит сайта и кода.** Находки привязаны к месту (страница и форма, файл и строка), к норме и к уверенности: «факт» или «требует проверки юристом». Код агент только читает, `.env` не открывает, правки вносит лишь с вашего согласия. Пример: «Проверь сайт https://example.ru на соответствие 152-ФЗ» или «Проверь, нет ли в коде проекта иностранных SDK и хранилищ за рубежом».
- **Документы.** 20 шаблонов: политика обработки ПДн, согласия на обработку и на распространение, сведения для уведомлений РКН (об обработке, о трансграничной передаче, об инциденте), приказы, акты, положение, правила внутреннего контроля и договор поручения. Реквизиты агент не выдумывает: недостающие поля запрашивает одним списком, текст берёт из шаблона без правок и с вашего согласия сохраняет, например, в `docs/152-fz/privacy-policy.md`. Пример: «Составь политику обработки персональных данных для нашего сайта».
- **Актуальность норм.** `check_norm_freshness` сверяет редакцию с официальным порталом и называет будущие редакции. Если портал недоступен, результат «не удалось проверить», а не «актуально».

## Как это работает

1. **Нормы — версионируемые файлы в репозитории.** Официальные тексты с датой редакции, источником и датой сверки ([ADR-0003](docs/adr/0003-knowledge-base-as-versioned-files.md)).
2. **Сервер не вызывает нейросеть.** Он отдаёт факты: тексты норм, находки правил аудита, заполненные шаблоны. Рассуждает модель вашего клиента, поэтому отдельный API-ключ не нужен ([ADR-0001](docs/adr/0001-deterministic-core-llm-in-host.md)).
3. **Цитаты — только из `get_norm`.** Модель находит нормы через `search_norms`, а текст для цитаты берёт из `get_norm`, не из памяти.
4. **Ответ сверяется кодом.** Перед отправкой `verify_answer` проверяет по базе идентификаторы норм, ссылки «ч. N ст. M», цитаты, даты редакций, метки уверенности и дисклеймер. Толкование он не проверяет.
5. **Аудит — правила, а не догадки.** У каждой находки есть правило, место, нормы и уверенность: `deterministic` или `needs-review`.

## База норм

| Акт                                                   | Что входит  |
| ----------------------------------------------------- | ----------- |
| 152-ФЗ «О персональных данных»                        | все статьи  |
| КоАП РФ                                               | ст. 13.11   |
| ПП РФ № 687 (обработка ПДн без средств автоматизации) | пункты 1–15 |
| ПП РФ № 1119 (требования к защите ПДн в ИСПДн)        | пункты 1–17 |
| Приказ РКН № 18 (согласие на распространение ПДн)     | пункты 1–9  |
| Приказ РКН № 178 (оценка вреда субъектам ПДн)         | пункты 1–6  |
| Приказ РКН № 179 (подтверждение уничтожения ПДн)      | пункты 1–8  |

Тексты берутся с официального портала актуальных редакций. Исключение — ПП № 1119: на портале его нет, текст взят с официального сайта Правительства РФ (government.ru), реквизиты официальной публикации указаны в ответе ([ADR-0014](docs/adr/0014-official-source-government-ru.md)). Приказ Роскомнадзора № 18 (требования к согласию на распространение) на портале опубликован только сканом: текст набран по скану, сверен с двумя копиями, срок действия приказа (до 01.09.2027) указан в ответе ([ADR-0015](docs/adr/0015-official-publication-scan-rkn-order-18.md)). Приказы № 178 и № 179 — тем же способом, срок действия до 01.03.2029, текст сверен с одной копией ([ADR-0016](docs/adr/0016-rkn-orders-178-179-harm-assessment-and-destruction.md)). Подробнее о составе, формате и обновлении — [в README базы](packages/knowledge/README.md).

## Ограничения

- **Нет ревью юристом.** Тексты норм сверены с официальными источниками, а шаблоны документов и правила аудита проверены автоматическими тестами и evals, но практикующий юрист их ещё не смотрел. Документы, которые пойдут в работу, показывайте юристу.
- **Нормы сверены на 13.11.2026, не на будущие даты.** Приняты, но ещё не вступили в силу и в базе не отражены: новая редакция 152-ФЗ с 01.03.2027 (в том числе ст. 22.1 и п. 7 ч. 2 ст. 10), изменения КоАП с 01.01.2027 и 23.01.2027, новая редакция ПП № 687 с 01.09.2030 (её содержание не изучалось). Приказ РКН № 18 действует до 01.09.2027, приказы № 178 и № 179 — до 01.03.2029. Протокол сверки: [docs/audits/2026-11-13-norms-check-v1.md](docs/audits/2026-11-13-norms-check-v1.md).
- **Только российское право.** Вопросы по GDPR и другому иностранному праву агент считает вне базы и не отвечает по ним как по нормам.
- **Аудит не заменяет проверку РКН.** Правила находят признаки нарушений; вывод о том, нарушение ли это, часто зависит от обстоятельств, и такие находки помечены «требует проверки».

<details>
<summary>Остальные ограничения: охват аудита, автопроверка актуальности, приказы РКН, сверка ответа, evals, комплект документов</summary>

- **Аудит видит не всё.** Он не заходит за авторизацию и не выполняет действия пользователя на странице. То, что проверить не удалось, попадает в раздел отчёта «не удалось проверить».
- **Актуальность не везде проверяется автоматически.** `check_norm_freshness` подтверждает редакцию 152-ФЗ, КоАП и ПП № 687; для ПП № 1119 и приказов РКН он отвечает `unknown`. Это значит «актуальность не подтверждена», а не «актуально»: проверяйте такие нормы по официальным источникам сами.
- **Профильные приказы РКН** в базе только № 18, № 178 и № 179: тексты набраны вручную по сканам опубликования, автопроверки изменений нет. Остальных приказов РКН нет.
- **Метки и сверка ответа неполны.** Метки уверенности иногда пропускаются, а `verify_answer` проверяет ссылки, цитаты, даты, числа, метки и дисклеймер, но не верность толкования: «сверка пройдена» не значит «ответ верен».
- **Evals нестабильны на отдельных кейсах.** Судьи шумят, выборки малы (один–пять запусков на кейс), нестабильность ниже примерно 30 % могла не проявиться.
- **Документы — не весь комплект.** Плагин составляет 20 шаблонов (список — `list_document_templates`). Он не составляет остальные локальные акты (например, инструкции пользователей информационных систем и модель угроз), уведомления об изменении сведений и о прекращении обработки. Сведения, которые норма перечисляет, но не наполняет (меры защиты, исполнители, места хранения, случаи оценки вреда и т. п.), шаблоны берут только у пользователя.
- **Аудит специальных категорий поверхностный.** Специальные категории и биометрию аудит сайта замечает только по словам в подписях полей форм («диагноз», «отпечаток» и т. п.) и помечает находку как требующую проверки; в исходниках, файлах, чатах и картинках он их не ищет. Он не проверяет маркетинг (ст. 15), данные не от субъекта (ч. 2–4 ст. 18), ответы на запросы и соблюдение ПП № 687 на деле (реестр носителей он только составляет по словам пользователя).

</details>

## Безопасность и приватность

- Содержимое проверяемых сайтов и репозиториев считается недоверенным: инструкции из него агент не исполняет.
- Сервер не хранит и не логирует персональные данные, найденные при аудите.
- Загрузка адресов защищена от SSRF.

Как сообщить об уязвимости — в [SECURITY.md](SECURITY.md). Принципы защиты — [ADR-0006](docs/adr/0006-security-untrusted-content-no-pd-retention.md).
