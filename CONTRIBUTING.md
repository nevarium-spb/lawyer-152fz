# Как участвовать в разработке

## Подготовка

Нужен Node.js ≥ 22.12. Менеджер пакетов — pnpm, версия закреплена в `package.json`.

```bash
corepack enable pnpm
pnpm install
```

На Windows без прав администратора: `corepack enable --install-directory "$(npm config get prefix)" pnpm`.

## Команды

| Команда                     | Что делает                                                          |
| --------------------------- | ------------------------------------------------------------------- |
| `pnpm check`                | всё сразу: формат, линтер, типы, границы модулей, тесты с покрытием |
| `pnpm test`                 | тесты                                                               |
| `pnpm lint` / `pnpm format` | линтер / автоформатирование                                         |
| `pnpm typecheck`            | проверка типов                                                      |
| `pnpm depcruise`            | проверка границ между пакетами                                      |
| `pnpm changeset`            | запись об изменении для релиза                                      |

## Процесс

1. Ветка от `main`: `feat/<веха>-<кратко>` или `fix/<кратко>`.
2. Сначала тест, потом код.
3. Коммиты в формате `тип(область): описание` — `feat(rules): правило PD-HTTPS`, `fix(scanner): ...`, `docs: ...`, `chore: ...`.
4. Изменение, которое попадёт в релиз, — с записью `pnpm changeset`.
5. Pull request проходит CI и ревью.

Критерии готовности задачи — в [PLAN.md](docs/PLAN.md#общий-критерий-готовности-definition-of-done-для-любой-задачи).
Архитектура и правила зависимостей — в [ARCHITECTURE.md](docs/ARCHITECTURE.md) и [ADR](docs/adr/).

## Добавить правило аудита

Один файл в `packages/rules/src/<область>/`, две фикстуры (с нарушением и без), ссылки только на существующие нормы.
См. [ADR-0004](docs/adr/0004-audit-rules-registry.md).

## Добавить или обновить норму

Только официальный текст и официальный источник (`sourceUrl`), дата редакции и дата сверки.
Комментарии и материалы коммерческих правовых систем не копируются. См. [ADR-0003](docs/adr/0003-knowledge-base-as-versioned-files.md)
и [ADR-0007](docs/adr/0007-license-agpl-and-legal-content-policy.md).
